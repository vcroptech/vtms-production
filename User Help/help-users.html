Only vCrop Admin can even open this screen

The Users screen doesn't appear in the menu for anyone else — not even Org Admin. It manages logins for Org Admin, Cluster Coordinator and Head Teacher only.

ⓘTeacher accounts are created from the separate Teachers screen's "Add teacher" button, not here. vCrop Admin's own account isn't creatable or manageable from any screen — it can't be disabled, and has no action buttons on its own row.
The role hierarchy
vCrop Admin — everything, everywhere
Org Admin — one organization
Cluster Coordinator — several schools
Head Teacher — one or more schools
Teacher — their own allocations only

What happens automatically on creation
Role createdAuto-synced
Org AdminThat organization's "Org Admin" pointer is set to this new user.
Head TeacherThe (first) selected school's Head Teacher pointer is set to this new user.

Every new user also gets a forced password change flag — they must set their own new password the very first time they log in with the one you gave them.

Managing schools after creation

Cluster Coordinator and Head Teacher accounts get a "Manage schools" button instead of a plain school cell — add or remove one school at a time. Removing or adding a Head Teacher's school keeps that school's Head Teacher pointer in sync automatically.

Enable / Disable and Reset password
ActionWhat it does
DisableBlocks that user from logging in at all, immediately — doesn't delete anything, fully reversible with Enable.
Reset passwordYou set a brand-new password directly and share it with the user yourself — VTMS doesn't email a reset link. Forces a password change at their next login, and automatically resolves any pending "Forgot password" request they had submitted.
ⓘWhen a user clicks "Forgot password?" on the login screen, it doesn't reset anything by itself — it just raises a request that shows up for vCrop Admin under Notifications → Password resets, waiting for an actual Reset password action here (or on the Teachers screen, for a teacher account).
