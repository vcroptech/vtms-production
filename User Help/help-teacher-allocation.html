Two ways to allocate a teacher
🔗 Linked to a Requirement

Pick a requirement whose candidate was Final Selected — this auto-fills the school and classes/day, and tries to auto-match the teacher by candidate name. Completing the allocation automatically marks that requirement Completed.

✍️ Manual, no requirement

Fill in Teacher, School, and Classes per day yourself — used for allocations that didn't go through the Requirements/Resumes pipeline at all.

ⓘOptionally list specific Class + Section + Subject rows at allocation time, or leave it for later via "Edit classes." Duplicate class/section rows are blocked before submission.
Classes per day vs. the specific class list — which number counts?

Classes per day (a plain number) and the specific Class/Section/Subject list are edited independently, so they can drift apart — e.g. allocated at 3/day, then 6 specific rows added later via "Edit classes" without ever revisiting the number. VTMS always uses whichever is larger as the real daily commitment, so a concretely-listed class can never go silently uncounted.

✓Effective classes/day = max(Classes per day, number of specific class rows listed). If you later add more specific rows than the original number, the number itself is automatically bumped up to match — never down.
The 6-classes/day cap — try it yourself

A school day has 6 class periods, so 6 is the most a single teacher can be committed to across all their active schools combined — not a per-school limit.

Editing classes later

"Edit classes" lets you add, change, or remove Class/Section/Subject rows for any of a teacher's active allocations — one section per school. Duplicate class/section rows are blocked per school. If the edited list ends up longer than the current classes/day number, that number is bumped up automatically to match, exactly like at allocation time.

De-allocating a teacher
FieldNotes
SchoolPick which specific school to end — other active allocations for this teacher are untouched.
Last working dateCan be a past or future date.
⚠A future last working date means the teacher is still genuinely teaching there until that date — they don't disappear from the school's active list immediately. Only once today's date passes the last working date does the allocation actually drop off.

De-allocating notifies Org Admin, the school's Head Teacher and Cluster Coordinator, and the teacher themselves — every message includes the actual last working date.

Cancel de-allocation

Available only while a de-allocation is still pending — i.e. the last working date hasn't passed yet. Cancelling restores the allocation to active and clears the last working date entirely, as if the de-allocation never happened. Once the last working date has actually passed, the allocation has fully expired and this option no longer applies.

Teacher account actions

Separate from allocation itself: Enable/Disable toggles the teacher's ability to log in at all, and Reset password issues a new password — both apply to any teacher who has a linked login account, regardless of their current allocation status.
